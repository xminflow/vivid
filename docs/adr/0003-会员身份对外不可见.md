# 会员身份对外不可见

安家立业的会员是**用户自助开通的付费门槛**，唯一权益是发起站内私信（见 `CONTEXT.md`「会员（安家立业）」）。做样式系统时必须回答一个问题：这个身份要不要像企业认证那样，在信息流、卡片、头像旁挂一枚标记。**决定：不挂。会员身份在小程序内对其他用户完全不可见，只在「我的」页与会员中心对本人显示。** 转化点押在权益被拦下的那一刻——非会员点「联系 TA」，当场引导开通。

于是代码里会出现一个反常现象：`author-row` 组件收 `certified`，却没有任何 `member` 相关的入参；整个前端搜不到一处会员的展示。这条 ADR 存在的目的，就是拦住将来某个人把它当成漏做的功能顺手补上——那一补，产品定位就从「私域社群的门槛」滑向了「消费 App 的会员等级」。

⚠️ **别和企业认证角标混为一谈。** 认证是对**读者**的可信度声明（这条内容背后是哪家公司、出事找谁），它必须可见；会员是用户与**平台**之间的付费关系，与读者无关。两者在 `CONTEXT.md` 里就是正交的，在界面上也不该长得像一对兄弟。

## 被否掉的选项

**头像旁挂会员标。** 行业惯例，也是转化最直接的做法：每一屏都在提醒非会员「别人有你没有」。问题是它把会员重新定义成了荣誉体系。安家立业收的是年费，对标付费社群——付费社群的门槛感来自「进不去」，不来自「进去的人戴了徽章」。更实际的伤害在浏览体验上：一个非会员每天刷几十条内容，就要被提醒几十次自己是二等公民，而他此刻并没有任何要联系谁的需求。这种提醒在他真正想联系人之前全部是负资产，只会让他更早离开——而他离开了，连那一次真正的转化机会也没有了。

**不挂标，但在信息流里投放开通入口或浮层。** 看起来温和，实际是同一件事换了个位置：它同样在用户没有需求的时候打断他，还额外占掉了内容的版面。而且这类入口的点击几乎全来自误触，转化数据会很好看、留存会很难看——用一个虚假的指标去指导二期定价，比没有指标更危险。

**挂标，但只对会员自己可见。** 想两头讨好：既给了付费者确认感，又不制造攀比。但「只有自己看得见的徽章」需要在每一处渲染作者信息的地方判断「这是不是我自己」，为一个纯粹的自我确认功能，把身份判断散进整个内容流的渲染路径。而自我确认在「我的」页已经完整给到了——那里有会员标识和到期日，用户想确认时知道去哪看。

**等有了数据再决定。** 听上去稳妥，实际是把决定拖到最贵的时候做：样式系统一旦定型，加一枚标记要动 `author-row`、三个板块的卡片、账号主页，还要重新平衡每张卡片上的信息密度。而一期根本产生不了能支撑这个决定的数据——私信还没上线，会员数只反映「有多少人愿意点一个免费按钮」。

## 代价与边界

**代价是一期几乎没有被动曝光渠道。** 会员的存在感完全依赖「我的」页那个入口，加上「联系 TA」被拦下的那一次。如果站内私信、随安而遇迟迟不上线，会员就是一个没人知道、也没理由开通的东西。一期会员数低是这条决定的**预期结果**，不是失败信号——一期本来就免费，那个数字既不代表收入也不代表意愿。真正要看的指标是二期上线后「被拦下 → 开通」的转化率。

**边界：这条决定绑定「会员唯一权益是发起私信」。** 一旦二期把权益扩展到对外可见的东西——内容优先曝光、专属标识的活动身份、会员专属板块——身份本身就成了展示物，这条决定自动作废，那时该重新开一份 ADR，而不是在这份上打补丁。

**「不可见」只针对小程序内的其他用户。** 管理后台必须能看到谁是会员（运营处理咨询时要知道对方身份，见 `docs/specs/0001-安家立业-会员与企业认证.md`），这不在本决定的范围内。

**转化文案的责任因此变重。** 全部转化压在被拦下的那一个瞬间，那句提示写得好不好，直接决定这门生意成不成。它不能只说「请先开通会员」——用户此刻正想联系一个具体的人，提示要接住的是这个具体的意图。这句话该在做私信时当成一个正经的设计问题来做，不是随手一个 `wx.showModal`。
